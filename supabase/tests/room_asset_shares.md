# 룸 자산 공유 메타데이터 (BE #3)

`public.room_asset_shares`는 기존 `assets.owner_id`를 소유권 기준으로 사용하고
`(asset_id, room_id)`를 기본 키로 저장한다. 기존 자산에는 공유 관계를 자동으로
추가하지 않는다. 자산·룸 삭제 시 연결된 공유 관계는 함께 삭제된다.

- 공유 생성: 자산 소유자이면서 대상 룸의 활성 구성원이어야 한다. 역할은
  `master`, `player`, `spectator` 모두 허용한다.
- 공유 해제: 자산 소유자만 가능하며, 소유자가 룸에서 탈퇴·제외된 후에도 가능하다.
- 공유 관계 조회: 소유자는 전체 공유 범위를 보고, 활성 구성원은 자신의 룸에
  대한 관계만 본다. 탈퇴·제외된 구성원과 비구성원은 해당 룸의 관계를 보지 못한다.
- 메타데이터 조회: 공유된 룸의 활성 구성원에게 읽기 권한만 추가한다. 소유자
  정보·자산 변경 권한·개인 폴더 권한은 기존 정책을 유지한다.

기존 룸 기능 권한에는 자산 라이브러리 전용 설정이 없으므로 활성 구성원 여부를
기준으로 한다. 맵·토큰 사용에 따른 기존 조회 권한은 별도로 유지된다.
마지막 라이브러리 공유가 해제되어도 다른 맵·토큰 사용 권한이 있으면 해당
권한에 따른 메타데이터 조회는 유지된다.

클라이언트는 `room_asset_shares`에 `asset_id`, `room_id`를 INSERT하여 공유하고,
두 키로 DELETE하여 해제한다. UPDATE는 허용하지 않는다. 중복 INSERT는
`23505`, 소유권·구성원 조건 위반이나 없는 대상 지정은 `42501`로 거부한다.
DELETE는 RLS가 행을 숨기면 오류 없이 0행을 반환하므로 반환된 행을 확인한다.

메타데이터 정책의 순환 참조를 피하는 `private.can_read_shared_asset`는 공유
관계와 현재 요청자의 활성 구성원 여부만 검사한다. `SECURITY DEFINER`와 빈
`search_path`를 사용하고, 비인증 실행을 금지하며 API에 노출되지 않는 스키마에 둔다.

이 문서의 테스트는 메타데이터를 담당한다. 라이브러리 공유에 따른 원본·썸네일
Storage 접근과 권한 회수는 [공유 자산 파일 접근](shared_asset_files.md)을 따른다.

## 로컬 검증

```sh
npx supabase test db --local supabase/tests/room_asset_shares.sql
```

pgTAP 테스트는 트랜잭션 안에서 데이터를 만들고 마지막에 롤백한다. 공유 전후
조회, 소유권·멤버십 검사, 중복/잘못된 대상, 여러 룸 공유의 독립성, 탈퇴·제외,
공유 해제, 비인증 접근, 삭제 시 관계 정리를 검증한다.
